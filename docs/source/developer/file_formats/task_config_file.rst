Task Files (.yaml)
==================

The task file aims to provide a standard way for users to create a synthesis task run. 
The task file is the key input file for users to craft, before running a batch of synthesis task.
The task file contains essential information required to set up synthesis scripts.

There are two types of task files
- Main task file, which includes a number of sub-tasks. See details in :ref:`file_format_task_file_main`
- Sub task file, which includes detailed task-level information. See details in :ref:`file_format_task_file_sub`

.. option:: config="<string>"

  Path to the sub task file (See details in :ref:`file_format_task_file_sub`). Should consider the default root is ``tests/tasks`` defined under the :ref:`_file_format_test_config_file`.

.. option:: golden_stats="<string>"

  Path to the golden result file, which contains the critical metrics and their expected values when running this task.

Benchmark Section
^^^^^^^^^^^^^^^^^

.. option:: benchmark_files="<string>"

  List all the design source files required to synthesis the benchmark. The default root is the home directory of current testcase. For instance, ``tests/tasks/quick_test``

.. note:: A number of design source files can be defined.

.. code-block::

  benchmark_files:
    - "benchmark/ram.v"
    - "benchmark/fifo.v"
    - "benchmark/counter.v"

Yosys Section
^^^^^^^^^^^^^

Under the node ``ys_template``, yosys-related settings are defined.

.. option:: path="<string>"

  Path to the template of yosys script when running this sub tsak. Should consider the default root is ``tests/ys_tmpl`` defined under the :ref:`_file_format_test_config_file`.

Options that are allowed in the yosys template file are defined under the node ``options``

.. note:: A number of options can be defined!

.. option:: <option_name>="<option_value>"

  Each option name is defined in the yosys template script. For example, in the yosys template, 

.. code-block::

  plugin -i rf-alkaid
  # Reserved lines for read benchmark files (design sources in verilog format)
  ${BENCHMARK_FILES}
  synth_rf_alkaid -family ${DEVICE_FAMILY} -blif ${BLIF_FILE} -top ${TOP_MODULE}
  
Two options are defined, ``DEVICE_FAMILY`` and ``TOP_MODULE``.
  
Each option value represents the actual value to replace the option in the template file when running this testcase.

For example, 

.. code-block::

  top_module: and2

This leads to the variable of ${TOP_MODULE} in the template file to be replaced with ``and2`` when running synthesis in this testcase.

QoR Check Section
^^^^^^^^^^^^^^^^^

Under the node ``qor_check``, *Quality-of-Result* Check -related settings are defined.

The QoR check is performed after each yosys run for each testcase.

Sensitive metrics and their values will be extracted from Yosys results, and then compare to the golden results.

A range of QoR shift can be set. Only the listed metrics are checked. If any out-of-range QoR shift is detected, an error will be thrown out.

.. note:: The metrics should be a valid one in the ``stat.json`` generated by Yosys. See the following example

.. literalinclude:: stat.json
  :language: json

In the example, the allowed metrics are ``$lut`` and ``dff``.

.. option:: upper_bound="<float>"

  Define the upper bound of QoR shift that is allowed for the current metric. Only positive numbers are allowed.``0`` means exact match. ``0.1`` means +10% than golden values is allowed.

.. option:: lower_bound="<float>"

  Define the lower bound of QoR shift that is allowed for the current metric. Only positive numbers are allowed. ``0`` means exact match. ``0.1`` in lower bound means -10% than golden values is allowed
